# ระบบจัดทำงานวิจัยและโครงงาน (project-dek-tcc)

เว็บแอปสำหรับจัดทำ **โครงงานนักเรียน/นักศึกษา** และ **งานวิจัยในชั้นเรียนของครู**
ผู้ใช้พิมพ์ requirement แล้วระบบดำเนินการให้ครบทุกขั้นตอน พร้อมไฟล์ Word และ PDF แยกตามโฟลเดอร์

| ขั้นตอน | ผลลัพธ์ (โฟลเดอร์) |
|---|---|
| วิเคราะห์ requirement | ชื่อเรื่องไทย/อังกฤษ วัตถุประสงค์ ตัวแปร เครื่องมือ สถิติ คำค้น (แก้ไขได้ในแท็บ “ข้อมูลงาน”) |
| 1) ค้นหาและดาวน์โหลดงานวิจัย | ไฟล์ PDF ฉบับเต็มอย่างน้อย 5 เรื่อง (เป้าหมาย 8) + สรุปงานวิจัย → `งานวิจัยที่เกี่ยวข้อง` |
| 2) บทที่ 1 | อ้างอิงเฉพาะงานวิจัยที่ดาวน์โหลดมาจริง → `บทที่ 1` |
| 3) บทที่ 2 | เขียนทีละหัวข้อ + ตารางสังเคราะห์งานวิจัย + กรอบแนวคิด → `บทที่ 2` |
| 4) บทที่ 3 | เว้นช่อง (ไฮไลต์เหลือง/เส้นประ) ให้เติมบริบทสถานศึกษา → `บทที่ 3` |
| 5) บทที่ 4 | ตารางผลเปล่าและช่องแปลผลให้เติมข้อมูล → `บทที่ 4` |
| 6) บรรณานุกรม | APA 7 สร้างจากเมทาดาทาของไฟล์จริง → `บรรณานุกรม` |
| 7) เอกสารสรุป | **โครงงาน:** แบบเสนอโครงงานตามแบบฟอร์มของสถานศึกษา → `แบบเสนอโครงงาน` • **งานวิจัยของครู:** โครงร่างงานวิจัย 3 บท (ปก + บทที่ 1–3 + บรรณานุกรม) → `โครงร่างงานวิจัย 3 บท` • แล้วส่งออก Word + PDF ทุกโฟลเดอร์ |

ไฟล์ทั้งหมดอยู่ที่ `storage/projects/<เลขงาน>/…` และดาวน์โหลดจากหน้าเว็บได้ทั้งรายไฟล์และ `.zip`

## ผู้ใช้ 3 บทบาท

| บทบาท | สร้างงานได้ | เอกสารขั้นตอนที่ 7 | สิทธิ์อื่น |
|---|---|---|---|
| **นักเรียน/นักศึกษา** | โครงงานเท่านั้น | แบบเสนอโครงงาน | สมัครเองได้ เลือกครูที่ปรึกษาได้ |
| **ครู** | งานวิจัยในชั้นเรียนเท่านั้น | โครงร่างงานวิจัย 3 บท (ไม่มีแบบเสนอโครงงาน) | สมัครแล้วรอผู้ดูแลอนุมัติ • *ดู + ให้ความเห็น* โครงงานของนักเรียนที่เลือกตนเป็นที่ปรึกษา (แก้ไขไม่ได้) |
| **ผู้ดูแลระบบ** | ทุกประเภท (รวมงานวิจัยและพัฒนา) | ตามประเภทงาน | จัดการผู้ใช้ ตั้งค่า AI และข้อมูลสถานศึกษา เห็นและลบงานทั้งหมดได้ แต่แก้ไขได้เฉพาะงานของตนเอง |

### การสมัครสมาชิก

- **ชื่อผู้ใช้คืออีเมล** (ไม่สนตัวพิมพ์เล็ก-ใหญ่ อีเมลหนึ่งสมัครได้ครั้งเดียว) — บัญชี `admin` ที่ระบบสร้างให้ตอนติดตั้งยังใช้ชื่อเดิม
- **นักเรียน/นักศึกษา** ต้องเลือกระดับ (ปวช. หรือ ปวส.) และกรอกกลุ่ม • **ครู** ไม่ต้องกรอกส่วนนี้
- **สถานศึกษา** เติมไว้ให้เป็น “วิทยาลัยพณิชยการธนบุรี” (แก้ได้ และเปลี่ยนค่าเริ่มต้นได้ที่ข้อมูลสถานศึกษาในเมนูผู้ดูแลระบบ)
- ระดับ กลุ่ม และสถานศึกษาถูกเติมลงฟอร์มสร้างงานให้อัตโนมัติ และแก้ภายหลังได้โดยคลิกชื่อผู้ใช้มุมขวาบน

### การแก้ไขงานเดิม

- **แก้ไขได้เฉพาะเจ้าของงาน** — ครูที่ปรึกษาและผู้ดูแลระบบเปิดดูและให้ความเห็นได้ แต่แก้ข้อมูล สั่งขั้นตอน หรือแก้เอกสารของผู้อื่นไม่ได้ (ผู้ดูแลระบบลบงานได้เพื่อจัดการระบบ)
- เจ้าของกลับมาแก้ได้ทุกเมื่อจากปุ่ม **✎ แก้ไขข้อมูลงาน** ในหน้ารายการหรือหัวหน้างาน: แก้ requirement ข้อมูลแบบเสนอโครงงาน และครูที่ปรึกษา แล้วเลือก “บันทึกการแก้ไข” (ไม่แตะเนื้อหาที่เขียนแล้ว) หรือ “บันทึกและให้ระบบทำใหม่ทั้งหมด”
- งานที่ขั้นแรกยังไม่สำเร็จ (เช่น ตอนนั้นยังไม่ได้ตั้งค่า API key) เมื่อเปิดกลับเข้ามาจะอยู่ที่หน้าแก้ไขพร้อมปุ่ม “บันทึกและเริ่มดำเนินการ”

### แนวการเขียนต่างกันตามประเภทงาน

| | โครงงานนักเรียน/นักศึกษา | งานวิจัยในชั้นเรียนของครู |
|---|---|---|
| ผู้ทำ / คำเรียกงาน | คณะผู้จัดทำ / โครงงาน | ผู้วิจัย / การวิจัย |
| จุดเริ่ม | ปัญหาหรือความต้องการของผู้ใช้ นำไปสู่การพัฒนาชิ้นงาน | สภาพปัญหาที่ครูพบในชั้นเรียนของตน |
| วัตถุประสงค์ | พัฒนา – หาประสิทธิภาพ (คุณภาพ) – หาความพึงพอใจ | เปรียบเทียบผลก่อน-หลังหรือเทียบเกณฑ์ – ความพึงพอใจ (มีหาประสิทธิภาพ 80/80 เมื่อสร้างนวัตกรรม) |
| สมมติฐาน | ไม่มี | มีเมื่อเปรียบเทียบ |
| ผู้ให้ข้อมูล | ผู้เชี่ยวชาญ 3 คน + กลุ่มตัวอย่างผู้ใช้ไม่น้อยกว่า 30 คน | กลุ่มเป้าหมาย 1 ห้องที่ครูสอน |
| วิธีดำเนินการ (บทที่ 3) | วงจรพัฒนาระบบ 7 ขั้น ซอฟต์แวร์/ฮาร์ดแวร์ที่ใช้ | แบบแผนกลุ่มเดียววัดก่อน-หลัง เครื่องมือและการหาคุณภาพ |
| สถิติ | ค่าเฉลี่ย ส่วนเบี่ยงเบนมาตรฐาน ร้อยละ | เพิ่มการทดสอบที (dependent) |
| ผล (บทที่ 4) | ผลการพัฒนาชิ้นงาน (เว้นที่ใส่ภาพ) – คุณภาพโดยผู้เชี่ยวชาญ – ความพึงพอใจ | ผลตามวัตถุประสงค์ ตารางคะแนนก่อน-หลัง |

ฟอร์มสร้างงานก็ถามต่างกัน: โครงงานถามชิ้นงานที่จะพัฒนาและข้อมูลสำหรับแบบเสนอโครงงาน ส่วนงานวิจัยของครูถามสภาพปัญหาในชั้นเรียนและวิธีสอนที่จะใช้
(งานที่เขียนไว้ก่อนการเปลี่ยนนี้: กด ↻ ที่บทที่ต้องการเพื่อเขียนใหม่ตามแนวของประเภทงาน)

## เริ่มใช้งาน

ต้องมี Python 3.10+ และ **Microsoft Word** บนเครื่องที่รันระบบ (ใช้แปลงเป็น PDF ให้ฟอนต์ไทยถูกต้อง) และฟอนต์ TH SarabunPSK

```powershell
pip install -r requirements.txt
python run.py            # หรือดับเบิลคลิก start.bat
```

1. เปิด http://127.0.0.1:5000 — ครั้งแรกระบบสร้างบัญชี `admin` และแสดงรหัสผ่านในหน้าต่างคำสั่ง (บันทึกไว้ที่ `storage/initial_admin.txt`)
2. เข้าสู่ระบบด้วย admin → เมนู **ผู้ดูแลระบบ** → ใส่ **Gemini API key** (ขอฟรีที่ https://aistudio.google.com/apikey) → กด “ทดสอบการเชื่อมต่อ AI”
3. เปลี่ยนรหัสผ่าน admin (คลิกชื่อผู้ใช้มุมขวาบน) แล้วลบ `storage/initial_admin.txt`
4. ผู้ใช้กด **+ สร้างงานใหม่** → พิมพ์ requirement → ระบบทำงานเบื้องหลัง ดูความคืบหน้าและ log ได้ในหน้างาน

ให้เครื่องอื่นในเครือข่ายเข้าใช้: `$env:HOST="0.0.0.0"; python run.py` แล้วเปิด `http://<IP เครื่องนี้>:5000`
(ตัวแปรอื่น: `PORT`, `THREADS`, `GEMINI_API_KEY`, `RESEARCH_STORAGE`, `NO_BROWSER=1`)

## การแก้ไขงาน

- ชี้ที่ย่อหน้า/ตารางแล้วกด ✎ เพื่อแก้เอง (ตารางพิมพ์ในเซลล์ได้ เพิ่ม/ลบแถวได้) • ✕ ลบ • ↶ ย้อนกลับ
- พิมพ์หรือกด 🎤 พูดคำสั่งให้ AI ปรับแก้เฉพาะจุด (ส่วนที่แก้จะไฮไลต์สีเขียว)
- กด ↻ ที่ขั้นตอนใดก็ได้เพื่อทำขั้นตอนนั้นใหม่ • แท็บ “งานวิจัยที่เกี่ยวข้อง” อัปโหลด PDF หรือเพิ่มจากลิงก์เองได้
- ถ้าเพิ่ม/ลบงานวิจัยหลังเขียนบทที่ 1–3 แล้ว บทนั้นจะมีเครื่องหมาย ⚠ เตือนว่าการอ้างอิงอาจไม่ตรงกับรายการปัจจุบัน จนกว่าจะกด ↻ เขียนใหม่
- ไฟล์ Word อัปเดตทันทีทุกครั้งที่แก้ไข ส่วน PDF แปลงใหม่ตอนกดดาวน์โหลดหรือสั่งขั้นตอนที่ 7 และแปลงเฉพาะเอกสารที่เนื้อหาเปลี่ยน

## แบบเสนอโครงงาน

สำหรับ**โครงงานนักเรียน/นักศึกษา** เอกสารขั้นตอนที่ 7 จัดตามแบบฟอร์ม “แบบเสนอโครงงาน แผนกวิชา…” ของสถานศึกษา และแก้ไขในหน้าเว็บได้เหมือนบทอื่น (รวมตารางขั้นตอนและช่องลงนาม)

- **ผู้จัดทำกรอกตอนสร้างงาน** (ไม่บังคับ): แผนกวิชา, ระยะเวลาดำเนินการ, ผู้รับผิดชอบโครงงานพร้อมเลขประจำตัว — ส่วนที่ไม่กรอกจะเป็นช่องให้เติม
- **ผู้ดูแลระบบตั้งค่าครั้งเดียว** ที่เมนูผู้ดูแลระบบ: ชื่อสถานศึกษา (พื้นที่ดำเนินการ), แผนกวิชาเริ่มต้น, ชื่อครูประจำวิชา หัวหน้าแผนกวิชา และรองผู้อำนวยการฝ่ายวิชาการ สำหรับช่องลงนาม
- AI ร่างหลักการและเหตุผล (อ้างอิงงานวิจัยที่ดาวน์โหลดไว้) ขอบเขต เป้าหมาย รายการค่าใช้จ่าย และประโยชน์ ส่วนตารางขั้นตอนเริ่มจากแผน 7 กิจกรรม 18 สัปดาห์ตามแบบฟอร์ม
- งานที่สร้างไว้ก่อนการเปลี่ยนนี้: กด ↻ ที่ขั้นตอนที่ 7 เพื่อสร้างแบบเสนอโครงงาน (ไฟล์เดิมในโฟลเดอร์ `โครงร่างงานวิจัย 3 บท` ไม่ถูกลบ)

## การอ้างอิง “จากงานวิจัยที่มีอยู่จริง” ทำอย่างไร

1. ค้นจาก ThaiJO (วารสารไทยในฐาน TCI) และ OpenAlex (วารสารต่างประเทศแบบเปิด) แล้ว **ดาวน์โหลด PDF ฉบับเต็ม** — รายการที่โหลดไม่ได้หรืออ่านข้อความไม่ได้จะถูกข้าม
2. เมทาดาทา (ผู้แต่ง ปี วารสาร เล่ม ฉบับ หน้า) อ่านจากแท็ก `citation_*` ของหน้าวารสารจริง AI ใช้เพียงอ่านไฟล์เพื่อสรุปและเติมส่วนที่หน้าเว็บไม่มี
3. ตอนเขียน AI ใส่ได้เพียงโทเคน `[[R1]]` / `[[@R1]]` แล้วโปรแกรมแปลงเป็น (ผู้แต่ง, ปี) เอง — โทเคนที่ไม่ตรงกับไฟล์ในโฟลเดอร์จะถูกตัดทิ้ง จึงไม่มีการอ้างอิงที่ไม่มีไฟล์รองรับ

> เนื้อหาเป็น **ร่าง** ที่ AI เขียน ผู้จัดทำต้องอ่านทวน ตรวจข้อค้นพบที่อ้างกับไฟล์ต้นฉบับ และเติมข้อมูลบริบท/ผลการทดลองจริงด้วยตนเอง

## โมเดล AI และโควตา

- โมเดลหลัก (ค่าเริ่มต้น `gemini-flash-latest`) ใช้เขียนเนื้อหา • โมเดลเร็ว (`gemini-flash-lite-latest`) ใช้คัดกรอง/อ่านงานวิจัย
- เมื่อโมเดลหลักไม่ว่าง ช้าเกิน 3 นาที หรือโควตาหมด (429) ระบบสลับไปใช้โมเดลเร็วอัตโนมัติ 10 นาทีแล้วค่อยกลับมาลองใหม่ (แจ้งใน log)
- หน้าผู้ดูแลระบบตั้งได้ว่าให้เขียนบทที่ 2 พร้อมกันกี่หัวข้อ (ค่าเริ่มต้น 1) — ตั้ง 3–6 เมื่อใช้ key แบบชำระเงิน บทที่ 2 จะเสร็จเร็วขึ้นตามสัดส่วน
- key แบบฟรีมีโควตาโมเดลหลักจำกัด งานหนึ่งเรื่องใช้ประมาณ 20–25 คำขอ หากต้องการคุณภาพการเขียนสูงสุดสม่ำเสมอควรใช้ key แบบชำระเงิน

สิ่งที่ชุดนี้ไม่ได้ตรวจคือคุณภาพเนื้อหาที่ AI เขียน การค้นจาก ThaiJO/OpenAlex จริง และการแปลง PDF ด้วย Word

| `app/prompts.py` | คำสั่งงาน AI ของแต่ละขั้น แยกตามประเภทงาน |
| `app/papers.py` | ค้น ThaiJO/OpenAlex ดาวน์โหลด PDF อ่านเมทาดาทา |
| `app/refs.py` | จัดรูปแบบ APA 7 และแปลงโทเคนอ้างอิง |
| `app/store.py` | เนื้อหาแบบบล็อก ประวัติการแก้ไข สร้าง Word/PDF/zip |
| `app/docbuilder.py` | ตัวสร้าง Word รูปแบบงานวิจัยไทย (TH SarabunPSK 16, ตัดคำไทย) |
| `app/editor.py`, `app/llm.py`, `app/db.py`, `app/config.py` | แก้ไขด้วย AI, ตัวเชื่อม Gemini, SQLite, ค่าคงที่ |
| `web/` | หน้าเว็บ (HTML/CSS/JS ไม่ใช้เฟรมเวิร์ก) |
| `tests/` | ชุดทดสอบอัตโนมัติ |

ข้อมูลทั้งหมด (ฐานข้อมูล SQLite, ไฟล์งาน, API key) อยู่ใน `storage/` ซึ่งไม่ถูก commit — สำรองข้อมูลโดยคัดลอกโฟลเดอร์นี้

## ข้อจำกัดที่ควรทราบ

- ระบบรันด้วย waitress (32 เธรด) รองรับผู้ใช้พร้อมกันทั้งห้องเรียนในเครือข่ายภายใน หากเปิดสู่อินเทอร์เน็ตควรวางหลัง reverse proxy ที่มี HTTPS
- การแปลง PDF ใช้ Word ทีละงาน (ประมาณ 5 วินาทีต่อเอกสาร) ถ้าไม่มี Word ระบบยังได้ไฟล์ `.docx` ครบ แต่ไม่มี PDF
- ไฟล์ PDF แบบสแกนภาพ (ไม่มีข้อความ) ใช้เป็นแหล่งอ้างอิงไม่ได้
